# SPMS – מערכת ניהול פדגוגי בית-ספרית

מערכת Web לניהול פדגוגי של בתי ספר (רשת של כמה בתי ספר בהתקנה אחת), בעברית ובערבית.

**מצב הפיתוח:** כל שמונת שלבי האפיון בוצעו. המערכת עברה בדיקת קבלה פנימית (177 בדיקות אוטומטיות) ומוכנה לפיילוט, בכפוף לנקודות שב-[docs/acceptance.md](docs/acceptance.md) – בראשן אישור משרד החינוך ותסקיר פרטיות.

**מסמכים:** [מדריך למשתמש](docs/user-guide.md) · [בדיקת קבלה](docs/acceptance.md) · [אבטחה ופרטיות](docs/privacy-and-security.md) · האפיון המלא: [docs/01-specification.md](docs/01-specification.md), מבנה הנתונים: [docs/02-erd.md](docs/02-erd.md), החלטות ארכיטקטוניות: [docs/decisions.md](docs/decisions.md).

## דרישות שרת

| רכיב | גרסה |
|---|---|
| PHP | 8.2 ומעלה, עם ההרחבות `pdo_mysql`, `mbstring`, `fileinfo`, `openssl`, `gd`, וכן `zip` (נדרשת לייבוא קובצי xlsx; בלעדיה ייבוא CSV עדיין פועל) |
| מסד נתונים | MariaDB 10.4+ או MySQL 8+ |
| שרת Web | Apache 2.4 (עם `mod_rewrite`) או Nginx |
| Composer | 2.x |

## התקנה

```bash
composer install --no-dev --optimize-autoloader
```

```bash
cp .env.example .env
```

1. ליצור מסד נתונים ומשתמש ייעודי בעל הרשאות למסד זה בלבד (לא `root`):
   ```sql
   CREATE DATABASE spms CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
   CREATE USER 'spms'@'localhost' IDENTIFIED BY '<סיסמה חזקה>';
   GRANT SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, INDEX, DROP, REFERENCES ON spms.* TO 'spms'@'localhost';
   ```
2. למלא ב-`.env` את פרטי המסד, `APP_ENV=production`, `APP_DEBUG=false`, `SESSION_SECURE=true`.
3. להקים את הטבלאות, ההרשאות ותפקידי המערכת:
   ```bash
   php bin/console migrate
   ```
4. ליצור מנהל מערכת ראשון. הסיסמה הזמנית מוצגת פעם אחת, והמערכת תדרוש להחליפה בכניסה הראשונה:
   ```bash
   php bin/console user:create-admin admin "שם מלא" --generate
   ```
5. להתחבר, ליצור בית ספר במסך "בתי ספר", ואז ליצור את משתמשיו.

### הגדרת שרת ה-Web

**שורש האתר חייב להיות התיקייה `public/` בלבד.** כל השאר (`app`, `config`, `storage`, `.env`, `vendor`) נשאר מחוץ להישג הדפדפן.

Apache:
```apache
<VirtualHost *:443>
    ServerName spms.example.org
    DocumentRoot /var/www/spms/public
    <Directory /var/www/spms/public>
        AllowOverride All
        Require all granted
    </Directory>
    # + הגדרות TLS
</VirtualHost>
```

Nginx:
```nginx
root /var/www/spms/public;
location / { try_files $uri /index.php$is_args$args; }
location ~ ^/index\.php$ { include fastcgi_params; fastcgi_param SCRIPT_FILENAME $document_root/index.php; fastcgi_pass unix:/run/php/php8.3-fpm.sock; }
location ~ \.php$ { return 404; }
```

בייצור המערכת חייבת לפעול ב-HTTPS בלבד (`SESSION_SECURE=true` מפעיל גם HSTS).

## פקודות console

| פקודה | פעולה |
|---|---|
| `migrate` | מריץ מיגרציות חדשות ומסנכרן הרשאות ותפקידי מערכת (אינו דורס הרשאות שנערכו ידנית) |
| `migrate:fresh` | מוחק ובונה מחדש – רק ב-`local`/`testing` |
| `seed:demo` | נתוני הדגמה פיקטיביים – רק ב-`local`/`testing` |
| `user:create-admin <user> "<name>" [--generate]` | יוצר מנהל מערכת |
| `backup` | גיבוי מוצפן של מסד הנתונים והקבצים ל-`storage/backups` ומחיקת גיבויים ישנים (להרצה לילית ב-cron) |
| `backup:verify <file>` | בודק שגיבוי נפתח עם המפתח הנוכחי ומכיל את הטבלאות |
| `backup:restore <file> --yes` | משחזר את מסד הנתונים מגיבוי (דורס את הקיים) |
| `backup:files <file>` | מפענח גיבוי קבצים לקובץ `.tar` |
| `notify` | שולח התראה במערכת על כל משימה באיחור, פעם ביום לכל משימה (להרצה יומית ב-cron) |
| `cleanup` | מוחק ניסיונות התחברות מעל 90 יום, רשומות יומן ביקורת מעל 24 חודשים וקובצי ייבוא שננטשו (להרצה יומית ב-cron) |

## הקמת בית ספר חדש – סדר העבודה

1. **שנות לימוד** – יצירת שנה (הראשונה נקבעת אוטומטית כנוכחית) והגדרת תקופות בתוך דף השנה.
2. **שכבות, מקצועות, חדרים.**
3. **מורים** – אפשר לקשר מורה לחשבון משתמש; הקישור הוא שקובע אילו כיתות ותלמידים המורה רואה.
4. **כיתות** – ובדף כל כיתה: שיבוצי ההוראה (מורה + מקצוע).
5. **תלמידים** – הזנה ידנית או ייבוא מקובץ xlsx/CSV עם תצוגה מקדימה.
6. בסוף השנה: **"פתיחת השנה הבאה"** בדף השנה מעביר את הכיתות והתלמידים לשנה חדשה ומשאיר את השנה הישנה כהיסטוריה.

### דוחות וייצוא

מרכז הדוחות (`/reports`) כולל 12 דוחות: הישגים (בית-ספרי, לפי שכבה, כיתה ומקצוע), התקדמות תלמיד, השוואה בין תקופות, תלמידים הזקוקים להתערבות, נוכחות, תוכניות לימודים, ביצוע תוכנית העבודה, משימות, וישיבות והחלטות.

- כל דוח נבנה פעם אחת כטבלה, וממנה נגזרים המסך, ההדפסה, קובץ ה-Excel וקובץ ה-PDF – ולכן הם זהים.
- דוח מציג רק את מה שהיקף הגישה של הקורא מתיר; ערך סינון שאינו ברשימת האפשרויות שלו פשוט אינו מתקבל.
- צפייה דורשת `reports.view` וגם את הרשאת הנתונים שהדוח נשען עליהם; ייצוא דורש `reports.export` ונרשם ביומן הביקורת (מי, איזה דוח, אילו מסננים, כמה שורות).
- ב-Excel כל טקסט נכתב כתא מחרוזת מפורש, כך שערך שמתחיל ב-`=` לעולם אינו מתפרש כנוסחה.
- קובצי הייצוא נוצרים ב-`storage/exports` ונמחקים אחרי כעשר דקות.

### איך מחושבים המספרים

- **ממוצע תלמיד במקצוע בתקופה** = Σ(ציון ÷ ציון מרבי × 100 × משקל) ÷ Σ(משקל), על הערכות מספריות שפורסמו. נעדר ופטור אינם נכללים (ואינם נחשבים אפס).
- **ממוצע קבוצה** (כיתה, שכבה, מקצוע, בית ספר) = ממוצע ממוצעי התלמידים.
- **שיעור נוכחות** = (שיעורים שהתקיימו − היעדרויות, כולל מוצדקות) ÷ שיעורים שהתקיימו. איחור נחשב נוכחות; שיעור שסומן "לא התקיים" אינו נספר.
- **ביצוע יעד** = שיעור הפעולות שבוצעו (כשיש פעולות), אחרת האחוז שדווח ידנית. "מתעכב" מחושב: יעד שלא הושלם ותאריך הסיום שלו עבר.
- דבר מאלה אינו נשמר: הכול מחושב מהרשומות בכל בקשה, ולכן אין נתון מצרפי שיכול לצאת מסנכרון.

### איתור תלמידים – עקרון הפעולה

בית הספר מגדיר קריטריונים (ממוצע נמוך, ירידה בין תקופות, כמה מקצועות מתחת לסף, היעדרויות). "הרצה" יוצרת אינדיקציות לבדיקה עם הנתונים שהובילו אליהן – ותו לא. המערכת אינה פותחת התערבות, אינה משנה סטטוס של תלמיד ואינה שולחת הודעות. ההחלטה (מעקב / התערבות / לא רלוונטי) נרשמת על שם איש הצוות שקיבל אותה, והרצה חוזרת לעולם אינה משנה אינדיקציה שכבר נבדקה.

### מידע רגיש – מי רואה מה בתהליכי העבודה

| מידע | גלוי ל- |
|---|---|
| תוכנית התערבות | מי שרואה את כיתת התלמיד במלואה, אחראי התוכנית, ומי שאחראי לפעולה בה |
| קשר עם הורים ופרטי הורים | מי שרואה את כיתת התלמיד במלואה, ואיש הצוות שתיעד. "תיעוד פנימי" אינו מופיע לעולם בסיכום המודפס להורים |
| תצפית ומשוב על מורה | הכותב, והנהלה שהיקפה כל בית הספר (קריאה בלבד). המורה עצמו – רק לאחר שהתיעוד שותף, בדף "הפיתוח המקצועי שלי" |
| ישיבה | המזמן, המשתתפים, והנהלה שהיקפה כל בית הספר |
| משימה | האחראי, מי שיצר אותה, והנהלה שהיקפה כל בית הספר |

פתיחת תוכנית התערבות, תיעוד קשר עם הורים, תצפית וכרטיס תלמיד נרשמות ביומן הביקורת גם כשהן רק נצפו.

### מי רואה מה

לכל תפקיד יש "היקף נתונים": *כל בית הספר* (מנהל, סגן, רכז פדגוגי, יועץ, מנהל מערכת) או *רק מה ששויך למשתמש*. משתמש בהיקף המוגבל רואה את הכיתות שהוא מלמד או מחנך, את הכיתות שבתחום תפקידו (רכז שכבה / רכז מקצוע), ותוספות ידניות שניתנו לו במסך המשתמשים (סמל העין). ההיקף נאכף בתוך שאילתות ה-SQL, כך שגם חיפוש, סינון וייבוא אינם חורגים ממנו.

ברמת המקצוע (ציונים, נוכחות, ביצוע תוכנית לימודים): מורה מקצועי רואה ומזין רק בשיבוצים שלו; מחנך ורכז שכבה רואים את כל מקצועות הכיתות שלהם; רכז מקצוע רואה את המקצוע בכל הכיתות. הזנה ותיקון – רק המורה של השיבוץ או מי שרואה את כל בית הספר. אינדיקציות האיתור מוצגות רק למי שרואה כיתה במלואה, משום שהן נשענות על נתונים מכמה מקצועות.

## גיבוי ושחזור

הגיבוי מכיל מידע אישי על קטינים, ולכן הוא תמיד מוצפן (AES-256-GCM; קובץ שנפגע או שונה אינו נפתח).

**הגדרה חד-פעמית** ב-`.env`:
- `BACKUP_KEY` – לפחות 24 תווים אקראיים. **יש לשמור עותק שלו מחוץ לשרת** (למשל בכספת סיסמאות של ההנהלה): בלי המפתח אי אפשר לפתוח אף גיבוי.
- `BACKUP_KEEP_DAYS` – כמה ימים לשמור גיבויים (ברירת מחדל 30).
- `MYSQLDUMP_PATH`, `MYSQL_PATH` – נתיב מלא כשכלי MySQL אינם ב-PATH (ב-XAMPP: `C:/xampp/mysql/bin/mysqldump.exe`).

**גיבוי:**
```bash
php bin/console backup
```
נוצרים `storage/backups/spms-<תאריך>.db.enc` (מסד הנתונים) ו-`spms-<תאריך>.files.enc` (קבצים מצורפים, אם יש). יש להעתיק אותם למיקום שני – שרת אחר או אחסון חיצוני; גיבוי שנמצא רק על אותו שרת אינו מגן מפני תקלת דיסק.

**בדיקת גיבוי** (אינה משנה דבר):
```bash
php bin/console backup:verify storage/backups/spms-20261115-083840.db.enc
```

**שחזור** – דורס את מסד הנתונים שמוגדר ב-`.env`:
```bash
php bin/console backup:restore storage/backups/spms-20261115-083840.db.enc --yes
```
```bash
php bin/console backup:files storage/backups/spms-20261115-083840.files.enc
```
ואז לפרוס את קובץ ה-`.tar` שנוצר לתוך `storage/uploads`.

**הפעלה מתוזמנת (Linux, crontab של משתמש השרת):**
```
15 2 * * * cd /var/www/spms && php bin/console backup  >> storage/logs/cron.log 2>&1
30 2 * * * cd /var/www/spms && php bin/console cleanup >> storage/logs/cron.log 2>&1
0  7 * * * cd /var/www/spms && php bin/console notify  >> storage/logs/cron.log 2>&1
```
ב-Windows: שלוש משימות ב-Task Scheduler שמריצות `C:\xampp\php\php.exe bin\console <פקודה>` מתוך תיקיית הפרויקט.

את `.env` יש לגבות בנפרד ובמקום אחר. גיבוי שלא נוסה בשחזור אינו גיבוי: מומלץ לשחזר לסביבת בדיקה אחת לרבעון (למשל עם `DB_DATABASE=spms_restore_check` זמני). תרגיל כזה בוצע בפיתוח ותועד ב-[docs/acceptance.md](docs/acceptance.md).

## אבטחה ופרטיות

פירוט מלא, כולל המסגרת החוקית, מדיניות שמירה ונוהל אירוע אבטחה: [docs/privacy-and-security.md](docs/privacy-and-security.md).

- **סיסמאות:** Argon2id; 10 תווים לפחות עם אות וספרה; סיסמה זמנית חד-פעמית והחלפה כפויה בכניסה ראשונה. שינוי או איפוס סיסמה מבטל את כל שאר ה-sessions של המשתמש.
- **התחברות:** נעילה אחרי 5 ניסיונות כושלים למשתמש או 20 לכתובת IP בתוך 15 דקות; הודעת שגיאה אחידה.
- **Session:** מזהה חדש בכל התחברות ומעבר בית ספר; HttpOnly + SameSite=Lax (+ Secure בייצור); ניתוק אחרי 30 דקות ללא פעילות.
- **בקשות:** CSRF על כל POST, כולל התחברות; הגבלת קצב לכל משתמש מחובר (120 כתיבות ו-20 ייצואים בדקה, ניתן לשינוי ב-`.env`).
- **פלט:** escaping לכל ערך; CSP ללא סקריפטים או סגנונות inline; כותרות `X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Cross-Origin-*`, ו-HSTS בייצור.
- **מסד נתונים:** prepared statements אמיתיים בלבד; מפתחות זרים מורכבים `(school_id, id)` – המסד עצמו מסרב לקשר רשומות של שני בתי ספר.
- **הרשאות:** הרשאה מוצהרת לכל נתיב, ובנוסף היקף גישה לפי כיתה ומקצוע בתוך כל שאילתה; רשומה מחוץ להיקף מחזירה 404.
- **קבצים:** רשימת סיומות סגורה, בדיקת תוכן מול הסיומת, שם אקראי, אחסון מחוץ ל-`public`, הורדה כקובץ מצורף בלבד. ייצוא Excel כותב טקסט כמחרוזת ולעולם לא כנוסחה; ייבוא קורא ערכים בלבד.
- **יומן ביקורת:** כל יצירה, עדכון, מחיקה, כניסה, הורדה וייצוא, וגם **צפייה** בכרטיס תלמיד, בתוכנית התערבות, בתיעוד קשר עם הורים ובתצפית. ללא סיסמאות.
- **גיבוי:** מוצפן, עם פקודות בדיקה ושחזור.

**נבדק אוטומטית:** CSRF על כל נתיבי ה-POST; סריקת XSS עם נתונים זדוניים בשדות הטקסט של כל המודולים, על 60+ דפים; fuzzing של כל הנתיבים בקלט עוין בלי שגיאת שרת; נגישות בסיסית (תוויות, שמות נגישים, כיתובי טבלאות) על אותם דפים.

**טרם מיושם:** אימות דו-שלבי; בדיקת חדירה חיצונית; אישור משרד החינוך ותסקיר פרטיות (PIA) – ראו [docs/acceptance.md](docs/acceptance.md).
